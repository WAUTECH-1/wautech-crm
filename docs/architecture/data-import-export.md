# Data import and export (Feature #17)

The synchronous API supports `companies`, `contacts`, `leads`, and `opportunities` through a resource allowlist. It uses Apache Commons CSV (RFC-style quoting, escaped quotes, commas, and newlines) and the existing domain services. CSV organization IDs are neither accepted nor trusted; the authenticated active organization is taken from `AuthenticatedOrganizationContext`.

## Endpoints and permissions

| Endpoint | Behavior | Permission |
|---|---|---|
| `POST /api/imports/{resourceType}/validate` | Multipart `file` preview; returns `totalRows`, `validRows`, `invalidRows`, and row/column errors without creating records | OWNER or ADMIN |
| `POST /api/imports/{resourceType}` | Multipart `file`; validates the complete file before writing and returns `processedRows` and `createdRecords` | OWNER or ADMIN |
| `GET /api/exports/{resourceType}` | Downloads versioned UTF-8 CSV, excluding archived rows | Any active CRM role with view access |

Unknown resources, non-`.csv` filenames, unsupported headers, invalid UTF-8, malformed CSV, and empty files return a safe 400 response. Files are limited to 5 MiB and 5,000 records. Error responses include at most 200 row errors; `invalidRows` still counts every invalid row. Exports use tenant-scoped repository pages and stop after 1,000 records, ordered by UUID ascending. The export response is `text/csv; charset=UTF-8` with an attachment filename ending in `-v1.csv`.

## Import columns

Headers are required, case-sensitive, and must match the complete ordered template. Blank optional cells become null. UUID references must identify active, non-archived records in the current organization. Contact and Opportunity company references are required; Lead company is optional. An Opportunity Contact, when given, must belong to its selected Company.

| Resource | Import header, in order |
|---|---|
| Companies | `name,website,industry,phone,email,status` |
| Contacts | `companyId,firstName,lastName,email,phone,jobTitle,status` |
| Leads | `firstName,lastName,email,phone,jobTitle,companyId` (status remains the domain default `NEW`) |
| Opportunities | `name,description,amount,currency,stage,expectedCloseDate,companyId,contactId` |

The existing Jakarta Bean Validation constraints are applied to each row. UUIDs use canonical UUID syntax, opportunity stages use the existing uppercase enum names, and dates use ISO `yyyy-MM-dd`. Amount and currency are validated together by the existing Opportunity request rule. A repeated identical record within one uploaded file is reported as a duplicate row; the existing CRM domains do not define cross-request natural-key uniqueness, so this feature does not invent it. Imported database IDs are generated by the domain services; import templates do not accept IDs.

Example company template:

```csv
name,website,industry,phone,email,status
Example Company,https://example.test,Software,,sales@example.test,ACTIVE
```

## Transaction, audit, and safety

Import parsing, validation, reference checks, and writes are synchronous. All rows and references are checked before the first write. Valid imports then invoke the existing domain service for each row within one transaction; any write or required audit failure rolls back the complete import. Each normal domain create audit remains in that transaction. Transfer preview, success, and failure events record resource type, outcome, and a count or safe failure code; raw file data and customer field values are never stored in audit metadata. Failure audits use the audit module's independent transaction so rollback does not discard the failure record.

Exports query only `organization_id = authenticated organization` and `archived = false`, in pages of 250, capped at 1,000 records. CSV cells beginning with `=`, `+`, `-`, or `@` after leading whitespace/control characters are prefixed with an apostrophe before CSV quoting to prevent spreadsheet formula execution. Commas, quotes, and line breaks are encoded by Commons CSV.

There are no job tables, background workers, external storage, or retries. A client may retry an import after a timeout; there is no cross-request idempotency key, so the response should be checked before retrying. Imports are limited to resources and fields supported by the existing CRM create operations; there is no delete, update, filter, or arbitrary table selection in this API. Export files are capped rather than streamed and do not provide filters.
