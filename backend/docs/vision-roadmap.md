## Proposed grounded AI MVP — P3, after CRM/release gates

One candidate story: “As an authorized user, ask what follow-ups are overdue and what changed in my current pipeline, and receive a factual summary linked to permitted source records.” “Changed” requires stored history that does not currently exist; initial release should answer current state and abstain from unsupported comparisons. A second approved story might draft a follow-up for human editing without sending it. Neither is an accepted SRS requirement yet.

Use the existing session, membership, service authorization and feature manifest. A backend read-only orchestration boundary selects a small, schema-validated set of tenant-scoped facts via existing domain services. It must not trust tenant IDs from a model, accept unrestricted SQL or expose unrestricted data/tools. Exact monetary values and currency remain strings/defined decimals end to end; summaries carry source IDs, retrieval time and known limits. Select a provider/deployment only after the owner accepts data residency, retention, cost/budget, secret handling and permitted data fields. Do not add a vector database or multi-agent architecture merely because a chat UI exists.

Retrieved CRM text is untrusted data: instruction-like record text must not redirect access or output private data. Tests include cross-tenant identifiers, another user's notifications, missing datasets, unsupported historical questions, currency mixing, fabricated sources, prompt injection in notes, timeouts, provider failures and obsolete tenant/session responses. Passing a fluent-answer demo is insufficient. Evaluations require factual reconciliation and refusal/abstention, with per-request safe diagnostics and a defined token/cost ceiling. No generated answer may change CRM records or send email in this initial proposed slice.

## Recommended sequencing

Complete and validate the CRM operational foundation first. Make an explicit owner choice between a reliable internal-alpha extension and an external-pilot release; the latter requires recovery/onboarding, secure staging, backup restore and isolation gates. After P0–P2 evidence, run a bounded P3 discovery/evaluation slice. P4 voice/multimodal/spatial work is research only in the 48-hour plan; D/G remain longer-term product hypotheses. No part of this audit commits the sole developer to every vision category or marks a concept as completed.
