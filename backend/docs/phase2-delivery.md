## API additions / compatibility

All paths below begin `/api`. Session cookie authentication and fresh CSRF on mutations remain required. `X-Organization-ID` selects a persisted active membership; it never grants access by itself. Existing error statuses remain 400 validation, 401 session, 403 permission/tenant, 404 unavailable scoped record; no stack traces or automatic mutation retries.

| Endpoint                                                              | Authorization / contract                                                                                                                                                                                                                                                |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /records/{resource}`                                             | Active member; companies, contacts, leads, opportunities, tasks, activities, notes. Zero-based `page`, `size` 1–100, `search`, allowlisted `sortBy`/`sortDirection` and resource filters. Response `{content,page,size,totalElements,totalPages}`. Active records only. |
| `GET /organization/eligible-members`                                  | Active member; minimal `{userId,name}` for enabled active same-tenant users.                                                                                                                                                                                            |
| `PATCH /tasks/{id}/assignee`, `/opportunities/{id}/owner`             | OWNER/ADMIN/SALES_USER; `{userId: UUID or null}`. Foreign/inactive recipient rejected.                                                                                                                                                                                  |
| `GET /pipeline-definitions`                                           | Active member; active definitions.                                                                                                                                                                                                                                      |
| `POST /pipeline-definitions`, `PUT/DELETE /pipeline-definitions/{id}` | OWNER/ADMIN; `{name,stages:[{key,name,outcome}]}`. 3–30 stages; unique stable keys, at least one OPEN, exactly one WON and LOST.                                                                                                                                        |
| `PATCH /opportunities/{id}/pipeline-stage`                            | OWNER/ADMIN/SALES_USER; `{pipelineId,stageKey}`. Same-pipeline open moves stay or advance one open stage; closing is allowed, reopening is rejected. Legacy `/stage` rejects configured deals to prevent bypass.                                                        |
| `POST /tasks/reminders/check`                                         | Active member; only principal's assigned overdue pending tasks; `{checkedCount}` bounded to 100 candidates.                                                                                                                                                             |
| `PATCH /notifications/{id}/unread`                                    | Active member; only current recipient/current tenant.                                                                                                                                                                                                                   |
| `POST /organization/ownership-transfer`                               | OWNER only; `{targetMembershipId}`. Active enabled same-tenant target, distinct from caller. Existing atomic service promotes target and demotes caller to ADMIN.                                                                                                       |

Existing array list endpoints, saved-view/notes/import/export routes and fixed pipeline reporting remain available. Opportunity amount is now an exact decimal JSON string; consumers must avoid converting it to Number for persistence. Organization settings use the existing name-only contract; no unapproved arbitrary settings store was introduced.

## Migrations and operational behavior

Apply V18–V22 in order through Flyway. Existing V1–V17 are unchanged. Empty PostgreSQL fixtures migrated all 22 versions successfully. V19/V20 add nullable assignment/configured-pipeline fields and tenant-composite FKs; existing tasks/deals remain unassigned/legacy. `APP_REMINDERS_ENABLED=true` opts into the existing Spring scheduler at one-minute intervals. Enable only on the approved single-instance deployment; scheduling defaults off. Manual reminders are available regardless. Notifications are stored in-app, refreshed on demand; no email/realtime or distributed scheduler claim.
